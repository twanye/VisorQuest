# 1.21.11 assessment (investigation only — nothing built or run for 1.21.11)

Scope: what it would take to add Minecraft **1.21.11** to this repo on top of the current
1.20.1 build. Findings are checked against the merged tree (`main` + `import/visor`,
`import/pojlib`, `import/atumvr`), upstream Visor `dev` as of 2026-11-25, and Modrinth.

## Bottom line

1.21.11 needs **no runtime or LWJGL change** (Java 21 and LWJGL 3.3.3 are already covered by
the bundled JRE 22.0.1 and `3.3.3-snapshot`). The cost is entirely in (a) the Quest port of
Visor/AtumVR 0.6.1 and (b) de-hardcoding Pojlib. **1.21.11 cannot be the first new target**
because the Quest Visor build does not exist yet in this repo.

## Verified facts

### Upstream Visor 1.21.11 target
`VisorModStudio/Visor` @ `dev` (pushed 2026-11-25), `multiversion.properties.toml`:

```toml
["1.21.11"]
java_version = 21
fabric_loader_version = "0.17.3"
fabric_loader_version_range = ">=0.17.3"
fabric_api_version = "0.141.6"
sodium_version = "mc1.21.11-0.8.14-fabric"
iris_version = "1.10.7+1.21.11-fabric"
```

Global: `atumvr_version = "1.14.0beta-snapshot#27"`, `lwjgl_version = "3.3.6"`.

Modrinth version `CUHDRyuw` = `Visor 0.6.1+mc1.21.11-fabric` (13.2 MB) +
`visor-0.6.1+mc1.21.11-fabric-api.jar` (1.8 MB), depends on Fabric API (`P7dR8mSH`).
As documented in `docs/VERSION_MATRIX.md` §2, these published jars contain no Android/Quest
code (`QuestVLoader`, `XRPlatform`, `AndroidXRBridge`), so they cannot be used as-is on Quest.

### What this repo already has
- `Visor/` is coah80's Architectury fork (no Stonecutter, `1.20.1` only). The 0.6.1 import and
  the first AtumVR Quest patch from the earlier session were never pushed and were lost when
  the repo was re-cloned. They must be redone.
- `Pojlib/src/main/java/pojlib/util/download` etc. are QuestCraft-6.0.0 lineage
  (`libltw.so` renderer), not 6.0.1/MobileGlues.

### Pojlib hard-coded 1.20.1 (all confirmed by grep)
| Location | What it pins |
|---|---|
| `Pojlib/src/main/java/pojlib/API.java:103-105` | `getQCSupportedVersions()` returns `{"1.20.1"}` — this feeds the launcher's version dropdown |
| `Pojlib/src/main/java/pojlib/install/Installer.java:305-308` | `installVisor()` throws `IOException` for any version except `1.20.1` |
| `Installer.java:388,395,416` | bundled mod versions are 1.20.1-only (`MoreCulling 1.20.1-0.24.5`, `Noisium 2.3.0+mc1.20-1.20.1`, `C2ME 0.2.0+alpha.11.18+1.20.1`) |
| `Pojlib/supportedVersions.json` | tops out at 1.21.5 |
| `Pojlib/mods.json` | versions 1.19.2 … 1.21.5; **no 1.21.11 entry** |
| `Pojlib/src/main/assets/mods/` | bundled `Visor.jar`/`VisorEssentials.jar` are 1.20.1 builds |
| `Pojlib/.../install/FabricMeta.java:53-77` | picks "latest" loader with a buggy comparison and ignores `stable`; currently 0.20.1, which happens to satisfy 1.21.11's `>=0.17.3`, but nothing pins it |

### Already compatible
- `Installer.installJVM()` downloads the QuestCraft `JRE.zip` (latest = OpenJDK 22.0.1) — meets
  the 1.21.11 requirement of Java 21.
- `JREUtils` JVM args (`-XX:+UseZGC -XX:+ZGenerational -XX:-ZProactive ...`) are valid on 22.
- `Installer.installLibraries()` skips every Mojang `lwjgl*` library, so Pojlib's
  `3.3.3-snapshot` bundle is what 1.21.11 will see; Mojang 1.21.11 also uses LWJGL 3.3.3.

## Work required, in dependency order

1. **Visor/AtumVR Quest port (P1) — prerequisite for every new version.**
   Re-import upstream Visor 0.6.1 and AtumVR 1.14.0beta, port coah80's patches
   (`a0275017`, `25740234`, `32c80265`; AtumVR `d04c1669`, `1d7dd401`), build a 1.20.1
   Quest jar and compare it with the working 0.4.0 artifact. 1.21.11 then needs a
   Stonecutter target built from the same patch set plus `fabric_loader_version 0.17.3`.
2. **Pojlib P0 (de-hardcode).** Own version table + mods manifest, remove the `installVisor`
   gate, remove bundled 1.20.1 mod versions from code, pin loaders per version, and decide
   bundle-vs-download for each Visor jar (a 1.21.11 Visor jar is ~13 MB).
3. **1.21.11 data.** Fabric API `0.141.6`, loader `0.17.3` minimum, and a fresh mod list
   (Sodium `0.8.14`, Iris `1.10.7`, plus whatever replaces the 1.20.1-only
   Noisium/BadOptimizations/MoreCulling/C2ME entries).
4. **Renderer risk.** `docs/VERSION_MATRIX.md` records that upstream QuestCraft only reached
   1.21.11 on Pojlib 6.0.1 (MobileGlues). This repo is 6.0.0/`libltw.so`; whether the GL 1.21.11
   rendering path works on `libltw` is **untested** and is the main reason 1.21.11 is rated
   med–high rather than low.

Because of (1), the cheapest first multi-version step is **1.21.1** (Visor target exists,
loader minimum already satisfied, `mods.json` already has an upstream entry), then
1.20.6/1.20.5, then 1.21.5 → 1.21.11. That is the order already recommended in
`docs/VERSION_MATRIX.md` §5.

## Decision requested

Choose one before code changes:

- **A (recommended)** — do step 1 now (Visor 0.6.1 + AtumVR Quest port, 1.20.1 first), then 1.21.1,
  then 1.21.11. Largest single chunk, but unblocks every other version and can be validated
  against coah80's known-good 1.20.1 artifact.
- **B** — do a narrow 1.21.11 spike first: import Visor 0.6.1, add only the 1.21.11 target,
  apply coah80's patches, and try to build a jar. Fast signal on compile/API breakage, but the
  artifact cannot be run on a Quest until Pojlib and the 1.20.1 parity work are done.
- **C** — Pojlib-only first: implement P0 against 1.20.1 (table-driven, gate removed, loader
  pinned) without touching Visor, so 1.21.11 later becomes a data change. Verifiable by
  `javac`/AAR build, still not runnable on Quest until step 1 lands.
